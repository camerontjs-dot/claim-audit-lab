Deterministic claim-to-evidence auditing.

Claim Audit Lab audits whether a draft claim is actually carried by the evidence supplied with it. It retrieves candidate passages, asks an NLI model whether they entail the claim, and then decides under a frozen, versioned rule set, so the verdict is reproducible and every step is on the record.

It does not search the open web, and it does not decide whether a statement is true of the world. It answers a narrower question: does the evidence you handed me support the claim you wrote?

What it is for

In regulated and high-stakes writing, the expensive failure is not a model that says something false. It is a claim that looks sourced and is not. CAL is built for the reviewer who has to find those. It takes a draft and an evidence bundle, and for each claim reports one of a small closed set of verdicts, together with the passage it read, the score it got, and the rule that produced the decision.

The design commitment is that the last word belongs to deterministic code. A language model contributes a signal; it does not get to be the verdict. Same inputs, same config, same output. Byte for byte.

Bounded, not clever

The probabilistic stage is sandwiched between a retrieval floor and a frozen rule layer. Neither can be talked out of its threshold by a confident model.

Abstains out loud

When evidence does not carry a claim, CAL says so rather than guessing. That rate is high, and it is published rather than hidden.

Everything on the record

Every audit writes a typed trace: passages, scores, features, rules fired, verdict, and the SHA of the rules file that decided it.

The three layers

Each layer answers a different question, and, as the chunk-granularity probe showed, they fail on disjoint populations. Fixing one does not shrink the other.

1

Retrieve

bi-encoder · probabilistic

Embeds the claim and every supplied passage, ranks by similarity, and admits only what clears the floor. Decides which evidence is in the room.

retrieval_floor 0.40 top_k 5
↓ admitted passages
2

Entail

DeBERTa-v3 NLI · probabilistic

Asks, per admitted passage, whether it entails the claim, contradicts it, or takes no position. Produces a signal, never a verdict.

supported_threshold 0.70 contradicted_threshold 0.70
↓ entailment signal
3

Rule engine

frozen · deterministic

Applies a versioned, SHA-pinned rule set over the signal plus structural features of the claim: negation, quantities, compounds, modal strength, scope. This layer, and only this layer, emits the verdict.

rules_version cal-rules-v1.13.0 families A1–A7 · B5 · C6a–f · P1–P2

Thresholds above are read from the shipped src/claim_audit_lab/v1/configs/cal-rules-v1.13.0.yaml. Changing any value changes the file SHA, which the loader pins and verifies at run time.

Install

Not yet published to PyPI. The public GitHub main is the earlier cal-rules-v1.5.0 history. This v1 engine lives on unpublished cal-v1-skeleton, install from a local checkout until a release is tagged. 

# from this checkout
python -m pip install -e ".[v1]"
python -m spacy download en_core_web_sm

axisvalueidentifies
distribution0.4.0the Python package
enginev1-retrieve-entail (ordinary audit/demo) · v0.2-lexical (selectable)which pipeline actually audits
rules versioncal-rules-v1.13.0the frozen decision layer inside the v1 engine

Package 0.2.0 and engine v0.2-lexical shared a number by accident, which read as though the whole package were the retired lexical matcher. The bump broke that collision. 0.3.0 was declared but never released and named several different trees while the v1 work was in flight, so the first public tag is 0.4.0, one version string, one tree.

Which command runs which engine

●

Ordinary audit and demo run v1-retrieve-entail. The retired v0.2-lexical matcher (falsified at 4/98 exact agreement, Cohen's κ ≈ 0) remains selectable with --engine v0.2-lexical. audit-bundle still follows the bundle's sealed pipeline field and defaults to v0.2-lexical so apparatus pins are not silently re-routed.

This is Track A packaging, not a tagged v1.0.0 release.

Run the built-in fixture demo (requires the [v1] extra; CPU DeBERTa; no API keys):

claim-audit demo --out-dir ./demo-out

Or audit a draft against an evidence bundle (same v1 engine):

claim-audit audit DRAFT.md --evidence evidence.yml --out ./report.md --json-out ./report.json
