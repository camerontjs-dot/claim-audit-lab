# Contract C RC1 Failed Attempts and Apparatus Deviations

Negative evidence is retained because the research question is about what survives falsification, not about producing a clean-looking schema draft.

## F1. Trace-only provenance binding

**Attempt:** derive a provenance-complete C1 from production `AuditTrace` bytes alone.

**Observed failure:** `AuditTrace` carries proposition identity, semantic/retrieval internals, verdict, config hash, and library version, but it does not carry the exact Contract-B bundle ID/hash/version from which the audit was executed.

**Consequence:** trace-only projection cannot satisfy the exact Contract-B binding criterion. Tests use an explicitly named fixture-surrogate binding only to study projection mechanics. The surrogate must not be cited as real B-to-C lineage evidence.

**Next discriminating test:** execute C0 capture at the actual CAL boundary where validated Contract-B identity and the emitted CAL result are both available, then verify immutable binding without modifying audit semantics.

## F2. Compatibility writeback as canonical Contract C

**Attempt:** consider existing Contract-B audited writeback as the smallest existing CAL result object.

**Observed failure:** production compatibility mapping collapses `contradicted` into `unsupported` and flattens multiple `not_checkable` reasons. Frozen same-headline traces show `no_evidence` and `no_entail_signal` are distinct producer states.

**Consequence:** writeback remains a compatibility/consumer projection. It is too lossy to be the universal semantic package under the preregistered diversity criterion.

## F3. Human report as semantic package

**Attempt:** reconstruct C1 from deterministic human report output.

**Observed failure:** report generation from C1 + renderer policy is deterministic, but reverse reconstruction loses exact Contract-B hash, producer code SHA, semantic measurement values, and reassessment lineage.

**Consequence:** human report is C3 presentation, not C1.

## F4. First normalized C1 as a compression win

**Attempt:** remove raw retrieval/logit/feature/probe telemetry and normalize the remaining semantic state into explicit families.

**Observed failure:** canonical byte size is larger than C0 on every frozen production trace measured:

- no-entail: 902 C0 vs 1,730 C1;
- contradicted-logging: 1,713 C0 vs 1,930 C1;
- numeric-uptime: 1,582 C0 vs 1,729 C1.

**Consequence:** the current candidate fails a stated promotion criterion. It must not be promoted merely because its conceptual separation is cleaner.

**Likely mechanism, still an inference:** explicit family names, repeated state envelopes, duplicated identity, and provenance binding add more bytes than raw telemetry removal saves.

**Next discriminating test:** factor run-level identity/config/evidence tables and use stable receipt/reference IDs while preserving the exact same consumer and report tests. Compare canonical bytes across multi-proposition runs, not just single-proposition examples.

## F5. Independently commissioned projector

**Attempt:** commission an isolated implementation through the available MainFrame Conduit surface.

**Observed failure:** the live adapter catalog returned no active adapters. No independent agent could be launched through that surface in this session.

**What was still built:** `contract_c_rc1_research/independent_projector.py`, a mechanically isolated implementation that imports neither CAL nor the producer projector and consumes only the candidate package mapping.

**Contamination status:** authorship occurred in the same research context. This is **not** independent reproduction and must not be described as such.

**Consequence:** the independent-consumer promotion criterion remains unmet.

## Apparatus deviation D1. Size-harness binding length

The first exploratory size calculation used one short fixed surrogate Contract-B binding. After freezing the measurement as an executable test, the harness used the per-fixture surrogate binding generated by the projector test helper. This increased the two larger C1 byte counts from 1,913 to 1,930 and from 1,712 to 1,729.

- The C0 bytes did not change.
- No semantic fixture changed.
- The direction and disposition did not change: candidate C1 remained larger than C0.
- The final report cites the frozen executable-harness numbers.

The earlier exploratory figures are retained here rather than silently overwritten.

## Operational limitation O1. Local repository acquisition

A direct network clone from the execution container was unavailable. Live repository inspection and mutation therefore use the connected GitHub surface, while deterministic research code was staged in a local scratch directory and is committed through Git object operations.

This is an operational limitation, not evidence about Contract C.
