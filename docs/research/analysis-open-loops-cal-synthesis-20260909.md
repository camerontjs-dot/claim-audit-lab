## 4. Loop 1 — What belongs inside CAL versus Evidence Bundler versus the Research Scaffold Harness?

### Observed

CAL #1 explicitly began at the Evidence Builder / Apparatus → CAL handoff. Claim discovery, decomposition, obligation generation, source collection, provenance generation, and upstream authority/status classification were outside that experiment. The same work supported full evidence-ledger preservation, nomination-lane invariance, separation of semantic measurement from source/trust metadata, and CAL ownership of proposition-specific eligibility through explicit assessment/policy state.

Production PR #14 hardened the same boundary. CAL's Contract B 1.2 intake keeps nomination/reviewer/process metadata and rejected candidates audit-visible but outside semantic input; hostile upstream support/refutation, semantic validity, applicability, completeness, decision-participation, verdict, and abstention keys fail closed. Provenance-bound temporal/version/context values remain facts rather than upstream applicability judgments.

The newer campaign adds a useful negative control. In #91, the true support can disappear inside the qualified EB retrieval aperture before admission. CAL then receives no admitted support and safely abstains. That is direct evidence that evidence-world formation and aperture remain upstream causal responsibilities rather than properties CAL can infer away.

### Counterevidence / boundary pressure

It would be too strong to conclude that decomposition can never live inside CAL. #45 and #47 froze deterministic decomposition mechanisms as candidate semantic machinery for bounded families. Those experiments show that decomposition can be a CAL-side measurement/interpretation technique when it is explicitly owned, frozen, and tested.

At the same time, #89 still requires an explicit typed strict-comparison target because a general raw-English target interpreter is not established. The product north star also treats automatic claim-decomposition correctness as a non-goal unless separately evidenced.

### Inference

The **authority boundary is no longer a broad open architecture question**:

- Evidence Bundler owns construction and preservation of the evidence world presented downstream, including candidate aperture, retrieval/admission history, provenance, and factual context.
- CAL owns proposition-relative semantic measurement, warranted relation, eligibility/applicability where explicitly assessed, blockers, abstention, and epistemic conclusion.
- The Research Scaffold Harness owns scientific controls whose purpose is experimental validity: frozen apparatus, isolation, mutation/metamorphic tests, evaluator checks, comparison and reproducibility receipts. Those controls do not acquire production semantic authority merely because they are useful research machinery.

A component can transport another component's facts or receipts without inheriting that component's decision authority.

### Remaining question

The genuine successor is narrower:

> When and where may raw-English claim decomposition / typed-target extraction occur without changing proposition meaning or smuggling unsupported semantic authority into CAL?

This is not answered by deciding a repository location in advance.

### Smallest discriminating experiment

Use the already-qualified strict-comparison vertical and freeze an automatic target/decomposition candidate before reveal. Compare its output against manually supplied proposition/typed-target controls on meaning-changing pairs, inverse propositions, entity collisions, scope traps, and explicit abstention cases. Hold the evidence world and downstream CAL machinery fixed.

Primary safety gate: **zero unsafe typed-target substitutions that lead to a deciding conclusion**. Count safe abstentions separately from exact recovery. Include a deliberately weak lexical/first-match target extractor so the evaluator must discriminate a gaming/fragile implementation.

### Proposed state transition

- broad component-authority question: **PARTIALLY RESOLVED → DECISION**
- automatic decomposition / target-extraction successor: **EXPERIMENT REQUIRED**

No production ownership change is authorized by this synthesis.

## 5. Loop 2 — Which CAL interfaces should be stable for v1.0.0?

### Observed

The repository has already done much of the semantic discovery that this question originally implied.

#31 tested the minimum epistemic state needed to keep materially different causes of support, refutation, abstention, exclusion, unresolved evidence, and execution failure reconstructable. Its bounded additive state/receipt candidate cleared the frozen A-K gate while preserving semantic measurement and production rule behavior. It supported retained/deciding/residual/excluded/unresolved participation state, explicit assessment execution state, separate execution status, restrained causal-basis claims, policy identity, nomination invariance, and source-fact / proposition-assessment separation.

#13 separately developed the CAL producer-side Contract C boundary: immutable B input binding, measurements, proposition-specific assessments, retained contribution state, decision/abstention, partial/failed execution, and a human-review boundary. That design work deliberately did not make every packaging choice canonical.

Contract C 1.0.0 is now an immutable released Apparatus surface at `5fe55f9ed5d0ee9f026ca1b077e9d70ce0487ea1`.

The authority-to-conclusion programme then falsified several tempting shortcuts before the current RC0 vertical was assembled:

- #77: an RC8J `WARRANTED` status alone is not a proposition conclusion and cannot justify naive Contract C strengthening;
- #78: caller-supplied scalar score can manufacture terminal threshold decisions and is therefore an unowned shortcut;
- #81: frozen RC1 accepted a stale `WARRANTED` result against a mutated non-warranted atom, producing a deciding contradiction. RC1 was falsified rather than repaired;
- #82-#84: bounded successors tied authority to captured/bound atom and exact proposition content while preserving fail-closed categorical composition.

Finally #88-#91 exercise exact Contract C 1.0 objects through the current RC0 path, and #90 carries those results into the maintained Decision Engine / Contract D boundary without treating Decision as Authorization.

### Counterevidence / restraint

This does **not** mean CAL itself is ready to declare `1.0.0`.

Production CAL `main` remains `32275a2...`, while the current RC0 path is an open Draft research stack. Contract C 1.0.0 is a separately versioned public artifact. A released downstream contract does not automatically make an experimental CAL producer/runtime a stable CAL application interface.

Production key lifecycle, general target extraction, broader semantic families, root composition, and some portability / compatibility questions remain unresolved. The current standalone and canonical surfaces also present non-checkability slightly differently: #89 can render user-facing `not_checkable`, while the canonical path in #91 carries `disposition=abstained`, `verdict=null`, plus a typed reason.

### Inference

The remaining work is not another architecture brainstorm. It is a **compatibility/stability audit** over concepts that have survived repeated experiments and consumer use.

Candidate concepts worth testing for a CAL stable shell include:

- immutable input / proposition / evidence identity bindings;
- strict, fail-closed parsing and explicit missing-state behavior;
- execution state distinct from epistemic disposition;
- supported / contradicted / abstained or equivalent non-strengthening result semantics with typed reasons;
- retained deciding/non-deciding contribution identity;
- explicit policy/operator/validation identity;
- exact Contract C binding and no-strengthening projection rules;
- explicit boundary between Decision and Authorization.

This list is a test target, not a version declaration.

### Smallest discriminating experiment

Build a bounded compatibility matrix across:

1. current production CAL public/observable output;
2. current RC0 standalone result/report;
3. exact Contract C 1.0 producer projection;
4. maintained Decision Engine consumer behavior.

For each candidate stable concept, mutate or omit the field/state and observe producer, validator, and consumer behavior. Include weak controls where aliases/defaults silently erase distinctions. Require old supported inputs to retain meaning where compatibility is claimed, and require missing critical state to fail explicitly rather than acquire a default.

The output should be a **CAL 1.0 compatibility proposal**, not a release. Versioning follows the observed consumer behavior, not the amount of implementation work.

### Proposed state transition

**PARTIALLY RESOLVED → DECISION / EXPERIMENT REQUIRED**

The semantic concepts have been heavily explored. The explicit CAL public compatibility promise has not.

## 6. Loop 3 — How should verdict uncertainty and reviewer disagreement appear in final reports?

### Observed: uncertainty

CAL has already accumulated substantial evidence against collapsing uncertainty into a scalar confidence or generic failure.

- #1 preserves explicit unknown/incomplete state, mixed evidence, blockers and non-deciding evidence.
- #31 treats assessment execution state separately from epistemic state and distinguishes not-performed, performed-unknown, performed-adverse, not-applicable and failed.
- #75 conservatively projected unresolved CAL state to Contract C `not_checkable` rather than strengthening it.
- #77 showed that a positive authority status cannot itself become a stronger proposition conclusion.
- #89 exercises supported, contradicted and safe not-checkable outcomes as successful CAL executions rather than process failures.
- #91 preserves contradiction separately from epistemic non-checkability downstream, preserves `mixed_categorical_relations`, and demonstrated order-invariant conflict abstention.

The #91 conflict case is especially useful: warranted support and warranted refutation were both admitted, both basis relation IDs remained visible, CAL produced `abstained / verdict=null / mixed_categorical_relations`, Contract C validated, and Decision held rather than selecting a winner.

### Observed: reviewer disagreement

Comparable evidence does **not** exist for human reviewer disagreement/adjudication.

#13 explicitly left open whether human adjudication belongs inside Contract C. The current research stack proves machine/result-state distinctions and admission effects, but it does not establish a canonical representation for two human reviewers who disagree about a CAL result or about an evidence/admission judgment.

### Counterevidence / alternative

It would be premature to add reviewer disagreement directly to Contract C simply because reports need to show it. Contract C's core ownership rule is CAL-attributable work bound to B. Human adjudication may be better represented as a separately attributable review/adjudication receipt linked to immutable C, or as a Decision Engine input, rather than rewriting the CAL result.

The fact that a human report is useful also does not make the human-readable rendering canonical. The current #89 pairing of machine result plus Markdown report is evidence that dual surfaces are feasible, not that every narrative field deserves contract status.

### Inference

Split the loop:

1. **Typed epistemic uncertainty/conflict:** substantially researched for the current strict-comparison fragment. Preserve canonical typed state/reasons and let reports project them without semantic strengthening.
2. **Human reviewer disagreement/adjudication:** genuinely open.

### Smallest discriminating experiment

Before a large reviewer-outcome study, test the ownership/representation seam.

Take fixed immutable Contract C results and collect two independently attributable reviewer annotations plus an adjudication outcome for a small set containing supported, contradicted, mixed, not-checkable, and intentionally misleading/incorrect CAL cases. Compare three additive representations:

1. mutate/embed review state directly inside C;
2. keep C immutable and attach a separate review/adjudication receipt bound to C;
3. treat reviewer/adjudication state solely as a Decision Engine input.

Require reconstruction of who said what, preservation of original CAL state, explicit disagreement, replayable downstream policy behavior, and no silent promotion of reviewer opinion into upstream evidence facts. A representation that requires rewriting the canonical CAL result after review should be treated skeptically unless the experiment demonstrates a need.

A later human-outcome experiment can then ask whether the selected presentation actually improves critical-finding recall, unsupported-conclusion rate, correction burden, calibration and appropriate override.

### Proposed state transition

- typed uncertainty/conflict: **PARTIALLY RESOLVED → DECISION / ARTIFACT** for the currently supported fragment
- human disagreement/adjudication: **OPEN → EXPERIMENT REQUIRED**

## 7. Cross-cutting negative evidence that must remain visible

This synthesis should not be read as a clean success narrative.

### RC1 stale-warrant replay

#81 falsified the first categorical authority-receipt architecture. A changed non-warranted semantic atom could still produce a deciding contradiction when paired with a stale `WARRANTED` result. Later candidates are meaningful partly because this failure remained frozen and became a replay killer.

### RC0 naturalistic span failure

#86 reached only 6/8 exact matches in the first naturalistic smoke. The `Women` / `Men` substring collision produced safe abstention instead of the expected refutation. #87 is a bounded successor, not permission to rewrite #86 as a pass.

### EB retrieval-aperture failure

#91 showed that the current qualified EB candidate aperture can exclude a real support passage under lexical-decoy pressure. Explicit admission cannot rescue evidence that never enters the candidate pool. The attempted wider profile was rejected by the integration guard, so this campaign does not establish a fix.

### Automatic target extraction remains absent

The current runnable CAL path deliberately requires explicit typed targets. The research record should not be summarized as though general natural-language decomposition or target extraction has been solved.
